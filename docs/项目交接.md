## 3. 本地运行与验证入口

从仓库根目录阅读 `docs/team/getting-started.md` 后配置环境。主 API 与 OCR worker 是两个进程；worker 需要兼容 Paddle 的 Python 环境。主系统从 `pdf_system/` 目录运行，以免相对存储路径指向别处。先复制 `pdf_system/.env.example` 为本机 `.env`，设置至少 32 字符的随机 JWT 密钥，勿提交密钥。

主系统的基本命令（在 `pdf_system/` 目录、已安装该目录依赖的 Python 环境中执行）：

```powershell
python -m backend.scripts.init_db
python -m uvicorn backend.main:create_app --factory --host 127.0.0.1 --port 8000
python -m pytest backend/tests -q
```

另一个终端在 `pdf_system/frontend/` 执行 `npm install`、`npm run dev`、`npm run build`。worker 的安装、模型下载和启动命令见 `pdf_ocr_module/ocr_service/README.md`，须使用其适配的 Python 环境。主系统与 worker 的数据库 URL、存储目录、JWT 密钥必须分别一致：`PDF_DATABASE_URL=OCR_DATABASE_URL`、`PDF_STORAGE_DIR=OCR_STORAGE`、`PDF_JWT_SECRET=OCR_JWT_SECRET`；相对路径应先规范成同一绝对路径。SQLite 可用于开发，MySQL 部署与并发行为须单独验收。

以上是**操作入口，不是本次执行记录**。初始化脚本的 `create_all()` 不迁移旧表；有历史数据库时先备份并核对 schema、配额流水。前端测试脚本和 OCR 测试开关随分支而变，切换到目标提交后再按该版本的 README、`package.json` 和测试说明执行。
