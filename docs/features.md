## 第 1 章 概述（约 6 页）

### 1.1 编写目的（0.4 页）
- 本文档的读者与用途：给设计/编码/测试三个后续阶段提供唯一基线；面向指导教师评审、组内开发分工。
- 明确文档边界：只描述"做什么"，不描述"怎么做"（实现细节留给概要设计）。
- 需求来源与获取方式：题目单、组内三次需求讨论、现有 OCR 模块代码走查、竞品试用。

### 1.2 项目背景与系统范围（0.8 页）
- 背景：纸质/扫描件档案数字化后，PDF 仍是"图片壳"，无法检索、无法复制、无法结构化利用；商用 OCR 需上云，涉密与个人材料存在出域风险。
- 一句话定位：**纯本地部署、离线可用、中文优先的 PDF 管理与 OCR 全文检索系统**。
- 系统边界（图 1-1 系统上下文图）：明确"系统内"与"系统外"（操作系统文件、外部大模型、云服务均不在范围内）。
- 范围内 / 范围外清单（表格）：范围内＝文件管理、在线阅读、OCR、校对、表格还原、导出、检索、权限、日志；范围外＝手写体专项训练、竖排与无线框表格、移动端 App、跨机分布式部署。

### 1.3 市场情况与相关产品分析（1.6 页）
- 市场趋势：无纸化办公 + 数据不出内网的合规要求，本地化 OCR 工具需求上升。
- **表 1-1 竞品对比矩阵**（6–8 个产品 × 8 个维度）
  - 对比对象：Adobe Acrobat Pro、ABBYY FineReader PDF、福昕 PDF 编辑器、WPS PDF、Paperless-ngx、Mayan EDMS、通用截图/扫描类工具（如白描、夸克扫描王）。
  - 对比维度：部署方式（云/本地）、数据是否出域、中文识别质量、OCR 后能否全文检索、表格还原能力、是否提供 API、授权与价格、二次开发难度。
- 竞品结论（3 条）：
  1. 商业软件识别质量高但闭源、按年订阅、无法嵌入自建业务系统；
  2. 开源文档管理系统（Paperless-ngx 等）具备归档与检索，但中文 OCR 与表格还原弱、阅读器体验一般；
  3. 空白点＝**本地推理 + 阅读器体验 + 中文全文检索 + 可嵌入 API** 四者兼备。
- 本系统的差异化定位与预期用户价值（表格：痛点 → 本系统对策）。

### 1.4 用户类型和特征（1.2 页）
- **表 1-2 用户角色与权限矩阵**（角色 × 功能：查看/上传/建任务/校对/导出/分享/管理）
  - 游客（未登录）：仅可打开分享链接，只读、有时效；
  - 普通用户 user：自己的文件全流程；
  - 只读用户 viewer：可查看、检索、导出，不可上传与校对；
  - 管理员 admin：全量资源、日志审计、配额与账号管理。
- 用户特征画像（每类 1 段：计算机水平、使用频率、核心诉求、典型挫败点）。
- 典型使用场景（3 个故事化场景，各 5–8 行）：研究生整理文献、行政人员归档扫描件、实验室共享设备手册。
- 用户规模与增长假设：单机部署 5–30 人、日均 50–200 页识别量（作为第 3 章性能指标的输入）。

### 1.5 操作环境（0.8 页）
- **表 1-3 运行环境要求**：客户端（Chrome/Edge 100+，1280×720 以上）、服务端（Windows 10/11 或 Linux，4 核 8 GB 起，CPU 推理，无需 GPU）、数据库（MySQL 8.0+ / 开发期 SQLite）、存储（本地磁盘，预留 ≥ 20 GB）。
- 网络环境：**可完全离线**，无外网依赖；模型权重随安装包分发并校验 SHA256。
- 部署形态：单机单体（API + worker + 数据库同机），支持后续拆分。
- 浏览器能力依赖：pdf.js 渲染、Canvas、Web Worker、Fetch/Stream。

### 1.6 设计和实现约束（1.2 页）
- **表 1-4 约束清单**（约束 → 类型 → 对需求的影响）
  - 技术约束：前端 React + pdf.js；后端 FastAPI + MySQL；OCR 引擎 PaddleOCR（本地 CPU 推理）；JWT 鉴权。
  - 合规约束：文件与识别结果不得离开本机；日志不得记录文件正文；第三方组件须为可商用开源许可（Apache-2.0/MIT），并在文档中致谢。
  - 资源约束：单文件 ≤ 20 MiB、≤ 100 页、单页 ≤ 2000 万像素；模型与依赖须能在 8 GB 内存机器上共存。
  - 进度约束：课程设计 12 周、3 人，需求阶段 2 周；据此裁剪功能优先级（MoSCoW）。
  - 团队约束：无专职运维，必须"一条命令启动"，避免引入消息中间件等额外组件（用数据库表实现任务队列）。
  - 范围约束：表格仅支持完整线框；不支持竖排与合并单元格（明确写入范围外，防止验收争议）。

### 2.1 系统总体功能结构（1 页）
- **图 2-1 系统功能结构图**（4 层：展现层 / 业务模块 / 服务模块 / 数据与存储）。
- **表 2-1 功能模块与需求编号总表**（模块 → 需求编号区间 → 优先级 → 对应章节）。
- 模块划分与组内分工对应关系（一人一模块主责 + 交叉评审）。

### 2.2 用户与权限管理（1.5 页）
- 功能点：注册、登录、登出、令牌刷新、修改密码、角色分配、账号禁用。
- 业务规则：用户名唯一且 4–32 字符；密码 ≥ 8 位含字母与数字，库内只存加盐哈希；令牌有效期与刷新策略；连续 5 次失败锁定 10 分钟。
- 异常与边界：重复注册、令牌过期、越权访问他人资源（返回 404 而非 403，避免资源探测）。
- 验收标准（Given/When/Then 各 2 条）。

### 2.3 文件管理（2.5 页）
- 功能点：上传（单/多文件、拖拽）、文件列表（分页、排序、按类型/时间/状态筛选）、重命名、删除（软删除 + 回收站）、分类（目录树）与标签（多对多、批量打标）、批量操作、合并/拆分 PDF、文件版本与代次。
- 业务规则：上传校验（扩展名 + MIME + 文件头魔数三重校验、大小与页数上限、加密 PDF 拒绝并提示）；同名文件自动加序号；删除需先取消进行中的任务；合并要求页数不超上限；拆分生成新文件而非修改原文件。
- 状态与流程：**图 2-2 文件生命周期状态图**（上传中 → 待识别 → 识别中 → 已识别/部分成功 → 已归档 → 回收站 → 物理删除）。
- 异常与边界：超大文件、页数超限、损坏 PDF、磁盘空间不足、并发同名上传。
- 界面要素清单（列表列定义、批量操作条、空态与错误态文案要求）。

### 2.4 PDF 在线阅读器（1.5 页）
- 功能点：连续/单页模式、缩放（50%–400%、适应宽度/页面）、翻页与跳页、缩略图侧栏、目录大纲、页内搜索与命中高亮、书签、矩形/文字批注、OCR 文本层叠加显示（可选中复制）、阅读位置记忆。
- 业务规则：PDF 原文件不落浏览器缓存以外的位置；批注坐标按归一化存储以适配缩放；文本层与图像层按页号对齐；旋转后坐标需变换。
- 性能要求：100 页文档首屏 ≤ 2 s，翻页 ≤ 300 ms（详见 3.1）。
- 与 OCR 的联动：识别完成后"原文/识别文本"双视图切换，点击识别框定位到原文位置。

### 2.5 OCR 识别（3 页，核心）
- 功能点：图片识别、PDF 整册识别、指定页范围识别、识别选项（语言、方向检测、表格还原开关）、异步任务提交与进度轮询、取消、失败重试、按页重试、能力探测（capabilities 返回当前实际可用的模型能力）。
- 业务规则：
  - 同一文件同时只允许一个活动任务，新任务使代次 generation +1，旧任务结果不得覆盖新代次；
  - 成功页不重复计算；失败页单独重试；
  - 任务默认最多 3 次尝试，退避 15 s、30 s；租约 120 s，每 40 s 续租，进程崩溃后由其他 worker 接管；
  - 页面结果与全文索引在同一事务内写入。
- 处理质量要求：横排印刷体中文字符准确率目标 ≥ 90%（以自建 200 页标注集计），识别框坐标以左上原点归一化返回。
- 边界与限制：手写体、竖排、无线框表格、公式不保证；扫描件分辨率低于 150 dpi 时提示质量风险。
- **图 2-3 OCR 处理活动图**（上传 → 校验 → 入队 → 领取 → 解码/分页 → 检测 → 识别 → 表格还原 → 回写 → 释放文件）。

### 2.6 识别结果校对（1 页）
- 功能点：按页查看识别框与原图对照、逐框改字、合并/拆分文本行、删除误检框、调整阅读顺序、保存修订、撤销。
- 业务规则：保存需携带 `expected_revision`，版本冲突返回 409 并提示重新加载合并；任务未结束不允许校对；校对后同步更新全文索引。
- 权限：viewer 不可校对；仅文件归属者与 admin 可校对。

### 2.7 表格还原（0.8 页）
- 功能点：自动识别完整线框表格、单元格文本归属、导出为表格结构、前端表格预览与手工修正。
- 业务规则：仅支持完整网格；无框线与合并单元格走降级策略（按行聚类为纯文本并标注"未还原"）。
- 准确率与失败提示要求。

### 2.8 结果导出（0.8 页）
- 功能点：TXT / JSON / CSV / HTML / XLSX 五种格式，支持整册或指定页，导出含/不含坐标。
- 业务规则：HTML 与 XLSX 必须转义，防公式注入（以 `=` 开头的单元格前置单引号）；文件名含原文件名与时间戳；导出为流式响应，不写临时大文件。

### 2.9 全文检索（1.5 页）
- 功能点：按关键词检索已识别文本、结果按文件聚合、命中片段高亮、点击跳转到对应页并定位、按文件/时间/标签过滤、检索历史。
- 业务规则：中文用 ngram 全文索引（MySQL `MATCH ... AGAINST`），长度 ≥ 2；单字符查询降级为子串匹配；仅检索有权访问的文件；返回结果标注来源 job_id 与 revision，避免展示过期文本。
- 性能要求：10 万页规模下 P95 ≤ 1 s。
- 异常：无结果、超长关键词（> 100 字符截断）、特殊字符注入。

### 2.10 分享与协作（1 页）
- 功能点：生成分享链接（可设有效期、提取码、是否允许下载）、取消分享、访问统计。
- 业务规则：分享链接为无状态签名令牌或随机串 + 数据库记录；过期或撤销后立即失效；被分享者仅只读；分享不复制文件实体。

### 2.11 配额、日志与统计（1 页）
- 功能点：用户配额（存储容量、月识别页数）、超额拦截、操作日志（谁、何时、对什么、做了什么）、使用统计看板（文件数、识别页数、成功率、平均耗时、存储占用）。
- 业务规则：入队前预留页数配额，超额返回 429；取消任务退还配额；日志不可修改、保留 180 天；统计按日聚合。

### 2.13 数据（数据库）需求（3.5 页）

#### 2.13.1 设计原则与约定
- 引擎 InnoDB、字符集 utf8mb4；主键统一 32 位 UUID（去横线）；时间统一存 UTC 的 `DATETIME`，展示层转换；金额/配额用整数；软删除用 `deleted_at`；乐观锁用 `revision`/`generation`。

#### 2.13.2 E-R 图
- **图 2-14 全局 E-R 图**（实体、联系、基数、可选性），并说明 3 处关键联系：用户—文件（拥有）、文件—任务（一对多、代次）、文件—文本索引（1:1 按页）。

#### 2.13.3 数据字典（核心，逐表给属性定义与约束）
按"表名 / 字段 / 类型(长度) / 允许空 / 默认值 / 键与索引 / 约束与取值域 / 说明"八列给出，覆盖以下 10 张表：

| 表 | 作用 | 关键约束（必须写明） |
|---|---|---|
| `sys_user` | 账号 | 用户名唯一、密码哈希、状态枚举、失败次数、锁定时间 |
| `sys_role` / `sys_user_role` | 角色与授权 | 角色枚举 user/viewer/admin，联合主键 |
| `file_category` | 分类树 | 父节点自引用、同级名称唯一、层级 ≤ 5、禁止成环 |
| `file_tag` / `file_tag_rel` | 标签与关联 | 标签名唯一、多对多联合主键 |
| `ocr_files` | 文件元数据 | `owner_id` 索引；`sha256` 去重判定；`page_count ≥ 1`；`generation ≥ 0`；`active_job_id` 可空；存储 key 与磁盘路径一一对应 |
| `ocr_jobs` | 识别任务 | 外键 → `ocr_files`；状态枚举；`attempts` 0–3；`lease_token`/`lease_until` 成对；联合索引 `(status, available_at, lease_until)` 支撑队列扫描 |
| `ocr_pages` | 页结果 | `(job_id, page_no)` 唯一；`page_no ≥ 1`；`status` 枚举；`revision ≥ 0`；结果 JSON 结构定义（框坐标、文本、置信度、行序） |
| `pdf_text_index` | 全文索引 | `(file_id, page_no)` 唯一；`LONGTEXT`；MySQL ngram 全文索引；与页结果同事务更新 |
| `share_link` | 分享 | 令牌唯一、过期时间、是否允许下载、访问次数 |
| `ocr_audit_log` / `quota_usage` | 审计与配额 | 日志只插不改；配额以"预留—结算—退还"三段式记账，剩余量非负 |

- 对 3 个 JSON 字段（`options`、`result`、`detail`）给出**结构定义与校验规则**：必填键、类型、取值范围、最大长度、未知键的处理策略（拒绝）。
- **表 2-x 状态枚举字典**：任务状态 6 值、页面状态 3 值、文件状态 5 值、用户状态 3 值，逐值给含义与可迁移目标。

#### 2.13.4 完整性约束与索引策略
- 实体完整性（主键、唯一键）、参照完整性（外键与删除策略：任务随文件级联、索引随页结果同事务）、用户定义完整性（取值域、CHECK、应用层校验清单）。
- 索引清单与用途（防全表扫描、支撑队列领取、支撑检索、支撑列表分页），并说明"不为低选择性字段建单列索引"的原则。

#### 2.13.5 数据量估算与容量规划
- 假设：1000 个文件 × 平均 30 页 = 3 万页；每页识别结果 JSON 约 4 KB、文本约 2 KB、页图约 150 KB。
- 结论：元数据表 < 100 MB，索引表约 60 MB，文件与页图占磁盘主要空间（约 5 GB/1000 文件），据此给出容量上限与告警阈值。

#### 2.13.6 数据保留、备份与清理
- 回收站保留 30 天、日志 180 天、失败任务中间态清理 7 天；备份策略（每日全量 + binlog）；清理任务不得破坏正在使用的租约。

## 第 3 章 其他需求（约 8 页）

### 3.1 性能需求（1.5 页）
- **表 3-1 性能指标**：页面接口 P95 ≤ 300 ms；100 页 PDF 首屏 ≤ 2 s；检索 P95 ≤ 1 s（10 万页）；单页 OCR ≤ 3 s（CPU，A4/300 dpi）；系统支持 10 并发上传、3 个 worker 并行；内存峰值 ≤ 4 GB。
- 度量方法与测试数据来源（自建 200 页标注集 + 生成的大文件样本）。

### 3.2 可靠性与可用性（1.2 页）
- 任务不丢：数据库队列 + 租约 + 幂等提交；进程崩溃后可接管；识别结果按页落库，支持断点续跑。
- 失败可解释：错误码表（E_UPLOAD_TOO_LARGE、E_PDF_ENCRYPTED、E_LEASE_LOST、E_QUOTA_EXCEEDED 等）与前端文案。
- 数据可靠性：事务边界、备份恢复目标（RPO 24 h / RTO 2 h，单机场景下的现实取值）。

### 3.3 安全性需求（1.5 页）
- 认证与授权：JWT（HS256，含 iss/aud/exp）、角色校验、资源归属校验、越权返回 404。
- 输入安全：三重文件类型校验、文件名净化、路径穿越防护、ZIP/XML 炸弹与 XXE 防护、导出公式注入防护、HTML 转义。
- 数据安全：密码加盐哈希、密钥仅存环境变量且 ≥ 32 字符、日志脱敏（不记录正文与令牌）、分享链接可撤销。
- 审计：所有写操作留痕，日志不可篡改。

### 3.4 易用性需求（0.8 页）
- 交互一致性（同一操作在同一位置）、关键操作二次确认、批量操作进度可见、错误提示可执行（说清原因与下一步）。
- 中文字体与排版、键盘快捷键（翻页、搜索、Esc 取消）、空态与骨架屏、无障碍基础要求（对比度、焦点可见、图片 alt）。

### 3.5 可维护性与可扩展性（0.8 页）
- 模块边界（OCR 作为独立可安装模块，通过 `install(app, settings)` 挂载，可与主系统分离部署）。
- 配置化（数据库 URL、存储路径、模型路径、限额全部走环境变量）。
- 可替换点：识别引擎、队列实现、存储后端各留一层适配；接口版本化与 OpenAPI 文档同步产出。

### 3.6 兼容性需求（0.5 页）
- 浏览器矩阵（Chrome/Edge 100+，Firefox ESR 只读可用）、操作系统（Win10/11、Ubuntu 22.04）、MySQL 8.0+ 与 SQLite 开发库的差异声明（全文检索能力不同，验收以 MySQL 为准）。

### 3.7 合规与法律需求（0.5 页）
- 用户上传内容的著作权提示；个人信息最小化（不采集与业务无关的身份信息）；第三方许可证清单（Apache-2.0/MIT/BSD）与致谢页；本地化部署满足数据不出域要求。

### 3.8 质量属性场景（1 页）
- **表 3-2 六个质量属性场景**：刺激源 → 刺激 → 制品 → 环境 → 响应 → 响应度量（覆盖性能、可用性、安全、可修改性、易用性、可测试性各 1 条）。

### 3.9 假设、依赖与风险（0.5 页）
- 假设：单机部署、用户量 < 30、无 GPU、管理员可信。
- 依赖：PaddleOCR 模型权重可用性、MySQL ngram 解析器、pdf.js 版本兼容。
- **表 3-3 风险表**：风险 → 概率 → 影响 → 应对（如 CPU 识别慢 → 限制并发与页数上限；表格识别不达预期 → 降级为文本并明示）。

### 3.10 验收标准与需求追踪（1 页）
- 验收方式：演示脚本（7 个场景）+ 自动化测试通过率 + 性能实测报告。
- **表 3-4 需求追踪矩阵**：需求编号 → 用例 → 设计章节 → 测试用例 → 验收结论（列留空，供后续阶段填写）。
