### 严重

**S1. 文档声称后端测试全过，与实机结果矛盾，且提交未推送**
- 位置：`docs/reviews/02-retest-validation.json:5`、`docs/reviews/02-retest-resolution.md`
- 现象：`validation.json` 记录 `backend_tests_passed: 137`（无失败）；但实机在 `5f5eb76` 上 `pytest` 结果为 **108 passed / 1 failed**。失败项是新增的 `tests/test_retest_review.py::test_concurrent_names_and_restore_collisions`（`422 invalid_storage_key`）。同时 `5f5eb76` 未 push，远端 CI 本轮未对新提交执行，所谓「全部通过」既与本地结果不符、也未经 CI 印证。
- 影响：reviewer 依据失真验收记录放行，实际存在未通过的测试与未验证的 Windows CI 矩阵。

**S2. `safe_path` 在 Windows 8.3 短名路径下误报 `invalid_storage_key`，导致上传偶发 422**
- 位置：`backend/core/media.py:22-26`（`safe_path`）、`modules/files/service.py:97-99`（`upload` 落盘前校验）
- 现象：实机 pytest 在 Windows 下 `storage_dir` 为 `C:\Users\ADMINI~1\...\Temp\...\storage`（8.3 短名），`storage.resolve()` 展开为长名 `C:\Users\Administrator\...`；并发上传时 `(storage/key).resolve()` 偶发保留短名，使 `is_relative_to(storage.resolve())` 失败、误抛 `invalid_storage_key` → `422`。单线程与弱并发上传均 `201`，4 线程真实并发（含 `real-api` e2e 的 `real concurrent uploads allocate unique names`）也 `201` 且名字去重正确——业务逻辑并发去重有效，失败源于路径规范化的环境竞态。
- 影响：在 Windows 含 8.3 短名或符号链接的部署/测试路径下，所有上传存在偶发 422 风险；该提交的并发测试在 Windows 本地不可靠，CI 若跑 Windows 矩阵会偶发失败。

### 一般

**G1. 并发去重无 DB 唯一约束，仅依赖应用层 `UPDATE` 抢锁**
- 位置：`backend/modules/files/service.py:56-76`（`lock_names` / `available_name`）、`backend/models/file.py:20-35`
- 现象：去重靠 `lock_names` 的无操作 `UPDATE User` 抢 SQLite 写锁，`available_name` 读快照去重；`File` 模型无 `(owner_id, name)` 唯一约束（`02-retest-resolution.md:21` 承认未加）。Windows 单进程实测 4 并发得到 `same.pdf/(1)/(2)/(3)` 互异，但 MySQL 多连接/多机下该写锁不跨连接，读快照仍会竞态。
- 影响：真实多进程部署下并发同名仍可能重复，修复未从存储层证明。

**G2. legacy `GET /api/v1/files` 列表端点仍返回裸数组、无 `total`**
- 位置：`backend/modules/files/router.py:37-41`、`frontend/src/features/management/pagination.ts:8-24`、`features/admin/UsersPage.tsx:19-23`、`features/files/TrashPage.tsx:30-36`
- 现象：新增信封分页（`core/pagination.py` + `/files/query`、`/files/trash`、`/auth/users`、`/audit`）已带 `total`，但旧列表端点未改；前端 `UsersPage`/`TrashPage` 仍 `readAllPages` 全量拉取（上限 1000 页 / 100000 条）。`real-api` e2e 已验证新端点的 `total`，旧端点未被覆盖。
- 影响：旧端点大账户仍全量返回，且翻页期间软删造成结果漂移、`seen` 去重只防重复不防漏项。

### 提示

**T1. 分享访问限速为单进程内存实现，多 worker/多机无效**
- 位置：`backend/modules/share/throttle.py`、`modules/share/router.py:80`
- 现象：`allow()` 用进程内计数器（30 次/分/IP）；文档注明多 worker 或容器化部署需前置网关。单进程实机有效，生产横向扩展后限流失效。
- 影响：提取码暴力枚举在集群部署下无速率限制。

**T2. 审计时间口径：页面按浏览器本地时区显示，CSV 导出为 UTC 原值**
- 位置：`backend/modules/audit/router.py`、`frontend/src/features/admin/AuditPage.tsx:57-65`、`src/features/management/management.ts:57-77`
- 现象：`created_at` 为 naive UTC；审计页前端转本地时区显示，CSV 直接导出 `2026-11-10T08:30:00`（无 `Z`），两者差 8 小时。`02-retest-resolution.md:40` 将其列为「非篡改」设计。
- 影响：同一数据在页面与导出文件中呈现不同时刻，易引发对账困惑。
