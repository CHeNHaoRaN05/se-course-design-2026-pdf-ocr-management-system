## 发现的问题

### 严重

**S1. `heartbeat` 同秒写成原值并依赖 rowcount 判定**

- 位置：`pdf_ocr_module/ocr_service/queue.py:55-58,39-42,47-50`、`ocr_service/db.py:9-11,98-99`、`ocr_service/docs/mysql-schema.sql:43`、`ocr_service/worker.py:27,45`、`tests/test_locking.py:26-34`、`tests/test_inventory_workflow.py:118`
- 现象：`update(Job).values(lease_until=stamp+lease_seconds)` 是仓内唯一「只写单列且用 `rowcount` 判定」的 UPDATE；`now()` 带微秒而 `lease_until DATETIME` 为 fsp=0，`db.py:98-99` 未显式设置 `client_flag`；worker 每页前必调 heartbeat、另有 40s 定时线程，页耗时 <1s 即同秒碰撞。
- 影响：无 `FOUND_ROWS` 时 `rowcount=0` → `worker.py:45` 误判租约丢失、`complete_attempt` 转 `retry_wait`；有 `FOUND_ROWS` 时 `rowcount=1` 但 `lease_until` 实际未延长，其他 worker 可提前接管。SQLite 保留微秒，现有测试全部测不出。

**S2. 任务取消不退款，`release_job` 是死代码，结算无服务端兜底**

- 位置：`pdf_system/backend/modules/ocr/quota.py:50-55`、`modules/ocr/router.py:63-81,65,70-72`、`modules/quota/service.py:36,46,59`、`modules/files/service.py:97-103`、`modules/ocr/lifecycle.py:18-26,37`、`frontend/src/features/ocr/OcrPanel.tsx:61-63`、`docs/contracts/C3-ocr-integration.md:34,38`、`C5-lifecycle.md:26`
- 现象：`release_job` 全仓仅 1 处定义，其余 3 处均为文档，无 Python 调用点。结算唯一入口需前端主动 POST；`pages_reserved` 只在 `settle` / `release` 才减少；取消路径只改任务状态不退款；`lifecycle.py:37` 删掉 `ocr_jobs` 后 `session.get(Job, job_id) is None` → 404，预留永久滞留。前端只在 `editor && TERMINAL` 轮询时触发 settle，页面关闭、请求失败、用户降为 viewer 时预留永久占用；`quota/service.py:36` 无过期回收、无后台任务。
- 影响：配额账目悬挂；`C3-ocr-integration.md:38` 把结算完全托付给前端，`C5-lifecycle.md:26` 称「ImportError 捕获降级」而实现是 `files/service.py:139-147` 的 `is_ready()` 判断。

**S3. `/jobs/{id}/retry` 在原预留之上再次预留额度，配额双扣**

- 位置：`ocr_service/api.py:173`、`pdf_system/backend/modules/ocr/quota.py:22-23,29-35`、`modules/ocr/router.py:78`、`docs/line03-implementation.md:30`、`tests/test_ocr_retry_flow.py:27-29`
- 现象：retry 再次调用 `ocr_before_enqueue(...)` → 再次 `reserve`，而 `reserved = len(job.options["pages"])` 仍是原始页数；`_close` 以 `(ref_id=job_id, reason=job_close)` 幂等，二次结算被拒，重试新增的预留既不退也不计费。测试只测「新建 job_id」。

**S4. 跨月结算与会计账实不符**

- 位置：`pdf_system/backend/modules/quota/service.py:32,43,45,49-50,57,61`、`models/quota.py:14-15`

**S5. 并发结算的幂等标记完全失效**

- 位置：`pdf_system/backend/modules/ocr/quota.py:29-30`、`backend/models/quota.py:28-38`、`modules/quota/service.py:15`、`tests/test_ocr_retry_flow.py:35-36`、`docs/contracts/C3-ocr-integration.md:37`

**S6. `/ocr/search` 不过滤回收站，与主系统 `/search` 权限口径分裂**

- 位置：`ocr_service/db.py:22-34`、`ocr_service/api.py:264-281`、`pdf_system/backend/modules/search/service.py:34`、`backend/main.py:54,59`、`modules/files/service.py:97-103`、`docs/architecture.md:178-179`、`modules/search/router.py:5`

- 影响：回收站文件的 OCR 全文仍可经 `/ocr/search` 命中。

**S7. `dev-token` 无 `jti`/`tv`，改密与登出后仍长期有效**

- 位置：`ocr_service/__main__.py:39-40`、`pdf_system/backend/core/principal.py:51,54`、`modules/auth/service.py:55,74,78`
- 现象：只含 `sub/role/iss/aud/iat/exp` 的 token：`GET /api/v1/auth/me` → **200**；`POST /auth/change-password` → 200；再用同一 token `GET /auth/me` → **200**。`"tv" in claims` / `"jti" in claims` 短路使改密、登出、刷新对该类 token 全部无效，直到 `exp` 才失效。

**S8. 配额结算的负值 / 零值边界无守卫，可静默错账**

- 位置：`pdf_system/backend/modules/quota/service.py:30,41-50,55,59-61`
- 现象：真实 SQLite 账户先 `reserve(10)`；`settle(-5)` → `(reserved=15, used=-5, 2 条流水)`；`release(5)` → 账户 `(10, -5)` 却记 `pages=-5` 流水（`:59` 只减 `min(5,1)=1`，`:61` 记 `-5`，账实差 4）。`settle` 无 `:30/:55` 的 `pages<=0` 守卫；`reserved=0, settle(pages=1)` 时 `moved=0` 仍写两条 0 值流水。
