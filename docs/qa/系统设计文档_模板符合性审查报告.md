## 四、发现的问题

### N1-01（P1）19 张建模图内嵌旧图号与旧图名，与本文档编号冲突

`docs/media/` 下的建模图是从需求分析文档迁入的成图，图片顶部自带需求阶段的编号，本文档正文与附录 B 已重新编号为「图 3-x / 4-x」，但图片未同步。抽查 5 张：

| 图片 | 图片内嵌标题 | 本文档图号与名称 |
|---|---|---|
| `image1.png` | 图1-1 系统上下文图 | 图 3-2 系统上下文图 |
| `image2.png` | 图2-1 系统功能结构图 | 图 3-1 系统功能结构图 |
| `image4.png` | 图2-3a OCR 任务创建与入队活动图 | 图 3-5 OCR 任务创建与入队活动图 |
| `image15.png` | 图2-11a 领域类图（**任务域**） | 图 3-15 领域类图（**文档域**） |
| `image17.png` | 图 2-12 系统部署图（单机 / 可离线部署） | 图 3-3 系统部署图 |

Word 正稿中图片上方有文档图题、图片内部又有旧图题，同一页出现两个不同编号；`image15` 连域名也变了（图片内容实际为文档与 OCR 域，文档称「文档域」更准确）。这是可直接目测的一致性缺陷，历轮审查只核对了正文图号与附录 B 索引，未检查图片内部文字。

处置建议（需先定方案）：① 批量重绘/覆盖 19 张图的内嵌标题为本文档图号；② 若不便改图，至少在 3.1 或附录 B 增加一条统一说明，明确「图片内编号为需求阶段旧号，以本文档图题为准」。

### N1-02（P2）模板要求的两类图件无同名图，运行环境与模板字面不符

- 模板三.1 明列「数据流程图」、三.2 明列「协作图」；全文检索「数据流」「协作图」「模块结构图」均为 0 处，附录 B 的 39 张图类型为结构图 1、上下文图 1、部署图 1、活动图 4、顺序图 4、状态图 3、类图 2、E-R 图 3、界面原型 20。按面向对象建模范式，4 张顺序图与协作图同属 UML 交互图、活动图承担流程表达，属**合理范式裁剪**；但教师若按模板字面逐项核对，会判为缺图。建议补 1 张数据流/模块结构图，或在 3.1 增加「模板图件 → 本文档图件」对照说明。
- 模板二.2 写「运行环境：Win，iOS，Android」；本文档 2.2 明确「桌面浏览器 + 单机服务端，不提供 iOS / Android 原生客户端」。该表述**符合项目真实情况**（需求文档亦如此约定），但与模板字面不符。建议在 2.2 增补一句「按题目约束不设移动端原生客户端，模板 iOS / Android 项不适用」，避免评审误解。

### N1-03（P3）其他观察项

- 图 3-2 内写「模型权重 models/ 离线分发 + SHA256 校验」，而表 2-2 写「不随源码包分发，首次部署需按清单下载」，需求文档附录 E 表 E-2 也把该项登记为「部分符合」。图内措辞偏乐观，建议统一为「按清单下载并校验，部署后离线可用」。
- 文档自称「概要设计说明书」，实际含 16 表逐字段数据字典、59 接口清单与算法参数，属详细设计深度。该项自 `docs/qa/系统设计文档_只读对抗性审查报告.md`（P2-3）起历轮持续记录，收敛报告已列为扩写型事项，本轮不重复展开。
- 图 3-1 展示的「管理控制台」「结果校对台」等为界面原型层面的设计目标，当前 React 前端仅 5 个页面；表 6-7 P1 已登记该差距，1.1 亦声明「未显式标注的条目为设计约定」，不构成事实错误。

## 五、结论

1. **模板覆盖**：设计文档按 PPT 第 153 页模板搭建，6 章 22 项全部有对应内容，4 项「略」按分工处理，另有 4 处增益；第 148 页的架构成果清单亦逐项承接。**无整章或整项缺失**。
2. **真实性**：本轮定向核查的模块目录、装配工厂、前端路由、OCR 17 接口、16 张表、进程端口、表 4-22 全部 28 个核心符号及抽查图件内容，均与仓库代码一致；未发现把未实现能力写成运行事实。
3. **待处理**：N1-01 为交付可见的系统性一致性缺陷（19 张图内嵌旧编号），N1-02 为模板字面项的两处偏差，建议提交前处理。其余为已登记或可接受事项。

审查阶段未修改任何交付文件；临时提取的课件文本与核查脚本已清理，模板原文已抄录于本报告第一节备查。
