## 第 1 章 概述（约 5 页）

### 1.1 编写目的（0.4 页）
- 本文档的读者与用途：给设计/编码/测试三个后续阶段提供唯一基线；面向指导教师评审、组内开发分工。
- 明确文档边界：只描述"做什么"，不描述"怎么做"（实现细节留给概要设计）。
- 需求来源与获取方式：题目单、组内三次需求讨论、现有 OCR 模块代码走查、竞品试用；本版按已实现代码与进度约束做了范围裁剪。

### 1.2 项目背景与系统范围（0.8 页）
- 背景：纸质/扫描件档案数字化后，PDF 仍是"图片壳"，无法检索、无法复制、无法结构化利用；商用 OCR 需上云，涉密与个人材料存在出域风险。
- 一句话定位：**纯本地部署、离线可用的 PDF 管理与显示系统，OCR 识别链路可跑通**。
- 系统边界（图 1-1 系统上下文图）：明确"系统内"与"系统外"（操作系统文件、云服务均不在范围内）。
- **范围内清单**：用户与权限、PDF 上传（含内容校验）、原文件下载、在线显示、文件管理（列表/重命名/标签/回收站/还原/彻底删除）、书签与批注增删查、分享链接、全文检索（关键词与 suggest）、OCR 识别任务（提交/进度/取消/重试/按页结果/导出）。
- **范围外清单（本版明确不做，不作为验收项）**：
  - 阅读器高级交互：连续/单页模式、适应宽度/页面、缩略图侧栏、目录大纲、页内搜索与命中高亮、OCR 文本层叠加（可选中复制）、阅读位置记忆、批注修改与撤销；
  - 文件管理高级：独立分类树（自引用层级、禁环）、文件版本与代次（版本列表/回滚/分支树）、批量操作条、合并/拆分 PDF；
  - OCR 高级：校对（逐框改字/修订冲突/撤销）、表格还原、识别选项中的语言与方向检测、低于 150 dpi 的质量提示、手写体专项权重、表格无框线降级、流式导出；
  - 检索高级：按文件/时间/标签过滤、检索历史、阅读器页内高亮；
  - 配额与运维：用户可见的配额写接口/容量上限/超额拦截、使用统计看板、审计日志保留与归档作业、200 页标注集准确率评测、生产部署脚本与恢复演练。
- 上述条目在代码或旧版文档中的残留接口，仅作为底层能力保留，不构成本版交付承诺。

### 1.3 市场情况与相关产品分析（1.2 页）
- 市场趋势：无纸化办公 + 数据不出内网的合规要求，本地化文档管理工具需求上升。
- **表 1-1 竞品对比矩阵**（6–8 个产品 × 6 个维度）
  - 对比对象：Adobe Acrobat Pro、福昕 PDF 编辑器、WPS PDF、Paperless-ngx、Mayan EDMS、通用扫描类工具。
  - 对比维度：部署方式（云/本地）、数据是否出域、PDF 阅读与管理能力、是否提供全文检索、授权与价格、二次开发难度。
- 竞品结论（3 条）：
  1. 商业软件功能完整但闭源、按年订阅，无法嵌入自建业务系统；
  2. 开源文档管理系统具备归档与检索，但中文体验与阅读器交互一般；
  3. 空白点＝**本地部署 + 可用的 PDF 阅读与管理 + 中文全文检索**三者兼备。
- 本系统的差异化定位与预期用户价值（表格：痛点 → 本系统对策）。

### 1.4 用户类型和特征（1 页）
- **表 1-2 用户角色与权限矩阵**（角色 × 功能：查看/上传/下载/导出/分享/管理）
  - 游客（未登录）：仅可打开分享链接，只读、有时效，可按链接设置下载；
  - 普通用户 user：自己的文件全流程；
  - 只读用户 viewer：可查看、检索、导出，不可上传；
  - 管理员 admin：全量资源、账号与角色管理。
- 用户特征画像（每类 1 段：计算机水平、使用频率、核心诉求、典型挫败点）。
- 典型使用场景（3 个故事化场景，各 5–8 行）：研究生整理文献、行政人员归档扫描件、实验室共享设备手册。
- 用户规模假设：单机部署 5–30 人；不作为容量规划的硬性输入。

### 1.5 操作环境（0.8 页）
- **表 1-3 运行环境要求**：客户端（Chrome/Edge 100+，1280×720 以上）、服务端（Windows 10/11 或 Linux，4 核 8 GB 起，CPU 推理，无需 GPU）、数据库（开发期 SQLite；MySQL 8 为可选）、存储（本地磁盘，预留 ≥ 20 GB）。
- 网络环境：**可完全离线**，无外网依赖；OCR 模型权重需另行下载并校验 SHA256，当前权重推理链路尚未跑通。
- 部署形态：本地单机（API + OCR worker + 数据库同机），不含生产部署脚本。
- 浏览器能力依赖：pdf.js 渲染、Canvas、Fetch；不涉及流式响应消费。

### 1.6 设计和实现约束（1 页）
- **表 1-4 约束清单**（约束 → 类型 → 对需求的影响）
  - 技术约束：前端 React + pdf.js；后端 FastAPI + SQLite（可选 MySQL）；本地 OCR 引擎；JWT 鉴权。
  - 合规约束：文件与识别结果不得离开本机；日志不得记录文件正文；第三方组件须为可商用开源许可（Apache-2.0/MIT），并在文档中致谢。
  - 资源约束：单文件 ≤ 20 MiB、≤ 100 页、单页 ≤ 2000 万像素。
  - 进度约束：课程设计 12 周、3 人；据此采用 1.2 的最小必须功能集。
  - 团队约束：无专职运维，"一条命令启动"，不引入消息中间件（用数据库表实现任务队列）。
  - 范围约束：见 1.2 范围外清单，验收时不追加。

### 2.1 系统总体功能结构（0.8 页）
- **图 2-1 系统功能结构图**（4 层：展现层 / 业务模块 / 服务模块 / 数据与存储）；业务模块仅含用户与权限、文件管理、PDF 显示、OCR 识别、检索、分享。
- **表 2-1 功能模块与需求编号总表**（模块 → 需求编号区间 → 优先级 → 对应章节）。
- 模块划分与组内分工对应关系（一人一模块主责 + 交叉评审）。

### 2.2 用户与权限管理（1 页）
- 功能点：注册、登录、登出、令牌刷新、修改密码、角色分配、账号禁用。
- 业务规则：用户名唯一且 4–32 字符；密码 ≥ 8 位含字母与数字，库内只存加盐哈希；令牌有效期与刷新策略。
- 异常与边界：重复注册、令牌过期、越权访问他人资源（返回 404 而非 403，避免资源探测）。
- 验收标准（Given/When/Then 各 2 条）。

### 2.3 文件管理（2 页）
- 功能点：PDF 单文件上传、文件列表与详情、按页信息、重命名、文件夹字符串归类、标签（多对多）、软删除、回收站、还原、彻底删除、原文件下载。
- 业务规则：上传校验以文件内容为准（魔数判定 PDF、页数上限、大小上限、损坏/加密 PDF 拒绝），同名文件自动加序号；删除需先取消进行中的 OCR 任务；原文件下载对登录用户开放，分享者按链接设置下载。
- 状态与流程：**图 2-2 文件生命周期状态图**（已上传 → 待识别/识别中/已识别 → 回收站 → 物理删除）。
- 异常与边界：超大文件、页数超限、损坏 PDF、磁盘空间不足、并发同名上传。
- 界面要素清单：列表列定义、空态与错误态文案、下载按钮位置。

### 2.4 PDF 在线显示（1 页）
- 功能点：pdf.js 渲染、上一页/下一页、按页码跳转、缩放 50%–300%、书签与批注的增/删/查。
- 业务规则：PDF 原文件通过带鉴权的 Range 请求直连后端，不额外落盘；批注坐标按归一化存储以适配缩放。
- 性能要求：100 页文档首屏 ≤ 2 s，翻页 ≤ 300 ms（详见 3.1）。
- 与 OCR 的联动：识别完成后展示识别框覆盖层，点击识别框定位到对应页。

### 2.5 OCR 识别（2 页，核心但仅要求跑通）
- 功能点：按文件提交整册识别任务、进度轮询、取消、失败重试、按页结果查看、能力探测（capabilities 返回当前挂载状态）。
- 业务规则：
  - 同一文件同时只允许一个活动任务，新任务使代次 generation +1，旧任务结果不得覆盖新代次；
  - 成功页不重复计算；失败页单独重试；
  - 页面结果与全文索引在同一事务内写入。
- 质量要求：**本版只要求链路跑通**（提交 → 识别 → 回写 → 检索/导出），不承诺准确率指标；横排印刷体 ≥ 90% 与 200 页标注集评测列入范围外。
- 边界与限制：手写体、竖排、无线框表格、公式不保证（范围外）；无语言/方向检测选项，无低分辨率提示。
- **图 2-3 OCR 处理活动图**（上传 → 校验 → 入队 → 领取 → 解码/分页 → 检测 → 识别 → 回写 → 释放文件）。

### 2.6 结果导出（0.6 页）
- 功能点：TXT / JSON / CSV / HTML / XLSX 五种格式，整册导出，可含/不含坐标。
- 业务规则：HTML 与 XLSX 必须转义，防公式注入（以 `=` 开头的单元格前置单引号）；文件名含原文件名与时间戳。
- 范围外：流式响应、指定页导出。

### 2.7 全文检索（1 页）
- 功能点：按关键词检索已识别文本、结果按文件聚合、结果片段预览、点击跳转到对应页、关键词建议（suggest）。
- 业务规则：中文用 ngram 全文索引（MySQL `MATCH ... AGAINST`），长度 ≥ 2；单字符查询降级为子串匹配；仅检索有权访问的文件；返回结果标注来源 job_id 与代次，避免展示过期文本。
- 异常：无结果、超长关键词（> 100 字符截断）、特殊字符注入。
- 范围外：按文件/时间/标签过滤、检索历史、页内命中高亮。

### 2.8 分享与协作（0.8 页）
- 功能点：生成分享链接（可设有效期、提取码、是否允许下载）、取消分享、访问统计、游客凭令牌只读访问与下载。
- 业务规则：分享链接为随机令牌 + 数据库记录；过期或撤销后立即失效；被分享者仅只读；分享不复制文件实体。

### 2.10 数据（数据库）需求（3 页）

#### 2.10.1 设计原则与约定
- 引擎 InnoDB（SQLite 开发库等价映射）；主键统一 32 位 UUID（去横线）；时间统一存 UTC 的 `DATETIME`，展示层转换；软删除用 `deleted_at`；并发代次用 `generation`。

#### 2.10.2 E-R 图
- **图 2-13 全局 E-R 图**（实体、联系、基数、可选性），说明 3 处关键联系：用户—文件（拥有）、文件—任务（一对多、代次）、文件—文本索引（1:1 按页）。

#### 2.10.3 数据字典（核心，逐表给属性定义与约束）
按"表名 / 字段 / 类型(长度) / 允许空 / 默认值 / 键与索引 / 约束与取值域 / 说明"八列给出，覆盖以下表：

| 表 | 作用 | 关键约束（必须写明） |
|---|---|---|
| `users` / `roles` | 账号与角色 | 用户名唯一、密码哈希、角色枚举 user/viewer/admin |
| `files` | 文件元数据 | `owner_id` 索引；`page_count ≥ 1`；同名按序号区分；`generation ≥ 0`；`active_job_id` 可空；`deleted_at` 软删除；存储 key 与磁盘路径一一对应 |
| `tags` / `file_tags` | 标签与关联 | 标签名唯一、多对多联合主键 |
| `bookmarks` / `annotations` | 书签与批注 | 归属文件与用户；批注坐标归一化 |
| `ocr_files` | OCR 镜像 | 与主系统 `files` 一一对应；代次与活动任务字段 |
| `ocr_jobs` | 识别任务 | 外键 → 文件；状态枚举；`attempts` 0–3；按页结果写入 |
| `ocr_pages` | 页结果 | `(job_id, page_no)` 唯一；`page_no ≥ 1`；结果 JSON 结构定义（框坐标、文本、置信度、行序） |
| `pdf_text_index` | 全文索引 | `(file_id, page_no)` 唯一；长文本；ngram 全文索引；与页结果同事务更新 |
| `share_links` | 分享 | 令牌唯一、过期时间、是否允许下载、访问次数 |
| `revoked_tokens` | 令牌失效 | 改密/登出后旧令牌失效 |

- 对 JSON 字段（`options`、`result`、`detail`）给出**结构定义与校验规则**：必填键、类型、取值范围、最大长度、未知键拒绝。
- **表 2-x 状态枚举字典**：任务状态、页面状态、文件状态、用户状态，逐值给含义与可迁移目标。

#### 2.10.4 完整性约束与索引策略
- 实体完整性（主键、唯一键）、参照完整性（任务随文件级联、索引随页结果同事务）、用户定义完整性（取值域、CHECK、应用层校验清单）。
- 索引清单与用途（支撑检索、列表分页、队列领取），并说明"不为低选择性字段建单列索引"的原则。

#### 2.10.5 数据量估算
- 假设：1000 个文件 × 平均 30 页 = 3 万页；每页识别结果 JSON 约 4 KB、文本约 2 KB、页图约 150 KB。给出元数据与索引的量级估算，不设容量告警阈值。

#### 2.10.6 数据保留与清理
- 回收站按手动彻底删除处理；不含日志 180 天保留、失败中间态定时清理与备份恢复作业（范围外）。

## 第 3 章 其他需求（约 5 页）

### 3.1 性能需求（1 页）
- **表 3-1 性能指标**：页面接口 P95 ≤ 300 ms；100 页 PDF 首屏 ≤ 2 s；检索 P95 ≤ 1 s（常规规模）；单页 OCR ≤ 3 s（CPU，A4/300 dpi，作为目标值）；系统支持 10 并发上传、单 worker。
- 度量方法与测试数据来源：生成的大文件样本与真实 PDF 样本；不建立 200 页标注集。

### 3.2 可靠性与可用性（0.8 页）
- 任务不丢：数据库队列 + 按页落库；识别结果按页保存，任务失败可单独重试。
- 失败可解释：错误码表（E_UPLOAD_TOO_LARGE、E_PDF_ENCRYPTED 等）与前端文案。
- 数据可靠性：事务边界（页结果与索引同事务）；不含备份恢复目标（范围外）。

### 3.3 安全性需求（1 页）
- 认证与授权：JWT（HS256，含 iss/aud/exp）、角色校验、资源归属校验、越权返回 404。
- 输入安全：文件内容校验（魔数）、文件名净化、路径穿越防护、导出公式注入防护、HTML 转义。
- 数据安全：密码加盐哈希、密钥仅存环境变量且 ≥ 32 字符、日志脱敏（不记录正文与令牌）、分享链接可撤销。

### 3.4 易用性需求（0.6 页）
- 交互一致性、关键操作二次确认、错误提示可执行（说清原因与下一步）。
- 中文字体与排版、空态与错误态文案；键盘快捷键、骨架屏、无障碍基础要求列为范围外。

### 3.5 可维护性与可扩展性（0.6 页）
- 模块边界：OCR 作为独立可安装模块，通过 `install(app, settings)` 挂载。
- 配置化：数据库 URL、存储路径、模型路径、限额全部走环境变量；OpenAPI 文档同步产出。

### 3.6 兼容性需求（0.4 页）
- 浏览器矩阵（Chrome/Edge 100+）、操作系统（Win10/11、Ubuntu 22.04）、SQLite 与 MySQL 的差异声明（全文检索能力不同，演示以 SQLite 为准）。

### 3.7 合规与法律需求（0.4 页）
- 用户上传内容的著作权提示；个人信息最小化；第三方许可证清单（Apache-2.0/MIT/BSD）与致谢页；本地化部署满足数据不出域要求。

### 3.8 质量属性场景（0.6 页）
- **表 3-2 质量属性场景**：刺激源 → 刺激 → 制品 → 环境 → 响应 → 响应度量（覆盖性能、可用性、安全、可修改性、易用性、可测试性）。

### 3.9 假设、依赖与风险（0.4 页）
- 假设：单机部署、用户量 < 30、无 GPU、管理员可信。
- 依赖：PaddleOCR 模型权重可用性、pdf.js 版本兼容。
- **表 3-3 风险表**：风险 → 概率 → 影响 → 应对；其中**"OCR 权重推理链路未跑通"列为首要风险**，应对为先按 `test_real_pipeline.py` 跑通一次真实识别，否则按 1.2 缩小演示口径并提前与指导教师确认。

### 3.10 验收标准与需求追踪（0.6 页）
- 验收方式：演示脚本 8 个场景——登录、上传 PDF、列表与详情、在线阅读与翻页、下载原文件、OCR 提交与结果查看、检索与跳转、分享访问与下载。
- **表 3-4 需求追踪矩阵**：需求编号 → 用例 → 设计章节 → 测试用例 → 验收结论；范围外条目不进矩阵。
