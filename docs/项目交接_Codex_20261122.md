## 2. 怎么跑起来

Python 环境为 conda `ocrpaddle`（Paddle 兼容）；前端为 Node 22。

```bash
# 后端：必须在 pdf_system/ 目录下运行，否则相对存储路径指向别处
cd pdf_system
python -m backend.scripts.init_db
python -m uvicorn backend.main:create_app --factory --host 127.0.0.1 --port 8000
python -m pytest backend/tests -q

# 前端
cd pdf_system/frontend
npm install && npm run dev
```

- 首次运行前复制 `pdf_system/.env.example` 为 `.env`，JWT 密钥至少 32 字符随机串，**不要提交**。
- 主系统与 OCR worker 是两个进程。若只演示文件管理与阅读，worker 不必启动；演示 OCR 需 worker（见 §6 P3）。
- 主系统与 worker 三组配置必须一致：`PDF_DATABASE_URL=OCR_DATABASE_URL`、`PDF_STORAGE_DIR=OCR_STORAGE`、`PDF_JWT_SECRET=OCR_JWT_SECRET`，且相对路径应先规范成同一绝对路径。
- `init_db` 的 `create_all()` 不迁移旧表。已有历史库时先备份并核对 schema。

### 4.4 CI 稳定性加固（2026-11-22）

`frontend-integration (windows-latest)` 的 live-smoke 步骤间歇失败（`#40`、`#56` 命中，`#51`–`#55`、`#57`、`#58` 通过）。定位依据是两组耗时对比：#56 该步骤 6 秒失败、#57 同一位置 10 秒通过，而应用代码相同，Playwright `expect` 默认超时 5 秒——失败点是"首个真实写请求"（注册：密码哈希 + 建表）在冷 runner 上超过 5 秒。

## 5. 续作硬约束（违反会破坏已建立的秩序）

1. **契约不可手改**。`docs/api-contract.yaml` 由 `backend/scripts/export_contract.py` 从实际路由生成。改任何路由后必须跑 `python -m backend.scripts.export_contract --check`，不一致会红在 CI。历史上手改/旧版覆盖曾删掉 3811 行。
2. **双账本语义不可混用**。页数额度记在 `job.options["pages"]`，配额预留记在 `job.options["_quota"]`；终态结算走 `settle_terminal`，释放走 `close_reservation`。二者不可互相替代。
3. **后台 reconcile 会干扰并发测试**。`mount.py` lifespan 起 30 秒周期任务，测试中会抢先结算；断言要按"最终态 + 账本条数"写，不要断言"恰好一次响应返回 settled"。
4. **`media.safe_path` 保持词法校验**。不要改回依赖短名展开的实现。
5. **提交纪律**：一次改动一个 commit，提交后打递增 tag；未提交的代码不得作为对照或对外称某版本结果。提交信息写"改什么 + 为什么 + 影响哪些产物"。
6. **大体积推送用分桶法**。单次 push 请求体过大会被网关重置（`curl 55 Send failure`）。方法：`git reset --soft <远端SHA>` → 以约 6MB 为上限贪心装桶 → 逐桶 `git commit -F msgfile -- <paths>` + `git push origin HEAD:refs/heads/main`，带重试；中断可续跑（不 reset，先推悬空 commit 再对剩余暂存重新分桶）。判定只看 `git push` 自身 returncode。注意 `reset --soft` 后 rename 的旧路径删除不会被带进桶，需单独 `git rm --cached` 再提交。
7. **交付物去个人化**。文档、脚本、示例不得出现本机绝对路径与个人身份信息；路径写 `/c/path/to/...`。
8. **不要动** `.workbuddy/`（项目记忆）、`_local/`、`tools/`、`历史文档/`、`uml/`、`prototype_img/`；这些是本机素材，已被 `.gitignore` 覆盖。

## 6. 未完成事项（按优先级）

### P1 规则集缺状态检查（唯一有实质风险的一项）

`.github` ruleset `protect-main` 只要求 1 名 code owner 批准，**没有 `required_status_checks`**。后果是 CI 红的 PR 仍可合入——历史上 PR #7 就是这样进来的。

处置：GitHub Settings → Rules → Rulesets → `protect-main` → 勾选 "Require status checks to pass"，加入 §1 列出的四个 job 名（逐字匹配）。**此项只能网页操作，无 API/CLI 通道**，Codex 若无法访问网页需交回人工。

附带决策：`require_last_push_approval=true` 在团队只有单一 owner 时会自锁（推送者与批准者同一账号则批准无效）。若要保留规则，合并前需由第二账号批准；若单人维护，建议关闭该子项。

### P2 需求文档 md 与 Word 正稿分叉

`docs/requirements/需求分析文档.md` 正文仍写"见 `docs/design/系统设计文档.md`"，那是 V1.0 路径，当前基线为 `系统设计文档_V2.0.md`。未改的原因是该 md 会被重新导出为 Word：只改 md 不重导出，两者立即分叉。

正确做法：改 md → 跑 `python scripts/export_req_docx.py` 重导出 docx → 两件一起提交。需 docx 生成依赖（python-docx / pandoc 之一），先确认本机可用。

### P3 真实 Paddle 权重推理未跑（R3）

OCR 链路代码齐、接口齐、测试骨架齐，但**真实权重从未端到端跑过**。可核验的痕迹：`ocr_service/evaluate.py:99` 把 `accuracy_acceptance_passed` 写死为 `None`，`ocr_service/tests/test_review_boundaries.py:25` 断言它确为 `None`——即"未验收"是当前被固化的状态，不是漏跑一次的结果。

注意：主系统 `backend/tests`（133 例）全绿**不代表** OCR 推理有效，那些用例走的是接口与账本，不加载真实模型。只有答辩需要现场演示 OCR 才必须补齐；补齐需要下载模型权重并配置 worker 环境。

### P4 MySQL 部署路径未验收

SQLite 用于开发；MySQL 的部署与并发行为没有单独验收记录。课程交付若只要求单机演示，可不做。

### P5 本机前端依赖缺失

`pdf_system/frontend/node_modules` 当前不存在（整理时清理过缓存与冗余），因此本机直接 `npm test` 会因 `ERR_MODULE_NOT_FOUND: typescript / esbuild` 挂在加载阶段，三份用例全部 fail。**这是环境问题，不是代码缺陷**——CI 绿即证明。接手第一步先 `npm install`。

## 7. 已知坑速查

| 症状 | 根因 | 处置 |
|---|---|---|
| 本地 `pytest` 跑到一半 `SystemExit` 或临时目录清理异常 | 沙箱 shim 的批量删除防护 | 加 `--basetemp=.pytest_tmp -p no:cacheprovider` 把临时目录指到项目内 |
| CI `frontend-integration (ubuntu)` 报浏览器下载失败 | runner 自带 Chrome，但 Playwright 仍去下载 Chromium | workflow 已注入 `PLAYWRIGHT_CHANNEL=chrome` 复用预装浏览器；`live-smoke.mjs` 读取该变量 |
| job 级 `env` 里用 `runner.os`，整个 workflow 0 job | job 级 env 只允许 `matrix`/`github`/`needs` 上下文 | 改用 `matrix.os` |
| PR 已 APPROVED 但 `mergeable_state=blocked` | `require_last_push_approval`，推送者与批准者同账号 | 见 P1；或换账号批准 |
| API 合并返回 `403 Resource not accessible by integration` | GitHub App 集成无 `contents: write` | 走本地 `git push` 快进；审批须已完成，不是绕过评审 |
| `git push` 报 `curl 55 Send failure` | 单次请求体过大被网关重置 | 分桶推送，见 §5.6 |
| `git merge-file` 对文档整篇冲突 | 那批文档是整篇重写，无共同锚点 | 以新版为基底，人工追补增量；不要指望三方合并 |
| docx 版本判断错误 | 检出后文件 mtime 全被重写为同一时刻 | 读 docx 内部 `docProps/core.xml` 的 `dcterms:modified` |
| Git Bash 里 `cd C:\...` 失败 | 反斜杠被当转义符吃掉 | 用 `cd /c/Users/...` 或带引号的正斜杠路径 |
