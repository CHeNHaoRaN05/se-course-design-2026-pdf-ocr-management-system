# 文档管理前端

基于仓库 `main` 的 `8cf647f`、`docs/prototype/index.html`、前端开发指南和工作区的需求分析文档完成。沿用 React 18、TypeScript、Vite 与 `/api/v1` 请求约定。

本次开发覆盖 PDF 阅读器、OCR 组件之外的管理页面。`src/features/reader/**`、`src/features/ocr/**` 和后端代码保持原样。原有阅读器由文件库和检索结果跳转进入，按需加载。

[查看页面截图](docs/PREVIEW.md) · [验证记录](docs/VALIDATION.md) · [后端接口对接待办](API_GAPS.md)

## 启动

```bash
cd pdf_system/frontend
npm ci
npm run dev
```

打开 `http://localhost:5173`。开发代理将 `/api` 转发到 `http://127.0.0.1:8000`，需要按上级 `pdf_system/README.md` 启动主系统 API，注册后即可登录。**应用不内置演示账号、假数据或自动登录**；浏览器测试中的数据只在测试拦截器中存在。

生产构建：

```bash
npm run build
npm run preview
```

部署 `dist/` 时，需要配置 SPA history fallback 到 `index.html`，并将 `/api/` 反向代理到主系统 API。浏览器公开分享链接指向前端的 `/share/:token`，因此该路径也需要 history fallback。

## 页面与功能

| 页面 | 路径 | 已实现 |
|---|---|---|
| 登录 / 注册 | `/login` | 邮箱登录、注册表单校验、密码显示切换、返回原目标页 |
| 文件库 | `/files` | 分类树、标签、名称搜索、类型与识别状态筛选、排序、分页、列表 / 卡片切换、多选、重命名、移动、打标、原文件下载、详情与 SHA-256 计算 |
| 上传 | `/upload` | 点击 / 拖拽多文件、类型 / MIME / 文件头 / 20 MiB 检查、同名序号、分类与标签、逐项进度、失败重试 |
| PDF 工具 | 文件库选中文档后打开 | 按选择顺序合并、顺序调整、页段 / 每 N 页拆分、新文件上传、100 页限制，保留原文件 |
| 回收站 | `/trash` | 删除确认、还原、彻底删除确认、批量结果、按 ID 还原、当前浏览器删除记录回退 |
| 全文检索 | `/search` | 全局搜索联动、文件补全、标签 / 日期过滤、结果按文件聚合、高亮、跳页、任务和修订号、账号隔离历史 |

| 访客访问 | `/share/:token` | 无需登录、提取码验证、失效提示、文档信息或授权下载 |
| 配额统计 | `/stats` | 当前账号文件数、存储量、配额已用 / 预留 / 剩余、任务状态分布与成功率 |

## 与现有后端的边界

这些限制在页面中明确提示，不能按已完成的服务端功能验收：

1. **回收站列表尚无接口**：已有 `POST /files/{id}/restore`、`DELETE /files/{id}/purge`。页面优先请求预留的 `GET /files/trash`，404 / 405 时退回当前账号在当前浏览器的删除记录（最多 1000 条），并提供按 ID 还原。缓存不含原文件，不是服务端完整清单；30 天定时清理尚未由现有后端实现，页面不假定文件到期。
2. **用户列表尚无接口**：已有角色与禁用的 PATCH 接口。预留的 `GET /auth/users` 不可用时仅显示当前账号和本次成功操作过的账号，仍支持输入目标 ID 管理。
3. **主系统审计查询尚无接口**：预留 `GET /audit`。未接入时显示“等待接入审计数据”，禁用导出，不用 `/ocr/audit` 冒充主系统审计。
4. **分类和标签按现有模型实现**：分类是文件上的路径字符串，标签为字符串。通过上传或移动创建分类；不新增空目录实体、目录移动接口或标签颜色字段。
5. **统计按服务端实际口径**：`/quota/overview` 统计当前账号；`/ocr-host/capabilities` 提供页数上限；`/ocr-host/usage` 提供任务数和成功页数。没有存储配额上限、每天趋势、平均耗时，不推算这些数值。OCR 未挂载时，文件和配额仍可展示。
6. **分享禁止下载的实际行为**：目前仅返回文件元数据，没有只读页面渲染接口。访客页说明此限制，不使用 iframe 等方式绕过权限。允许原文件访问时提供授权下载；本次不另建阅读器。
7. **认证遵循实际代码**：后端用邮箱而非用户名登录；刷新为当前 JWT 轮换，没有独立 refresh token。本次保留手动续期，业务请求 401 时清除本地凭据并跳登录。

三个预留读取接口的建议结构和接入位置见 [API_GAPS.md](API_GAPS.md)。本次未改变后端 C1–C5 契约、数据库结构或团队成员负责的 OCR / 阅读器实现。

## 实现说明

- `shared/http.ts` 为唯一请求出口，兼容既有 `api` / `apiBlob` / `tokenStore` 签名；统一处理 FastAPI 的 detail、校验错误、网络错误和 401。所有鉴权下载带 Bearer；公开分享请求不携带当前用户 JWT。
- `AuthProvider` 校验 `/auth/me` 后才进入工作空间，支持跨标签页登录状态变化；读取账号失败允许重试，不把未知权限视作普通用户。
- 当前文件列表没有 total 和服务端排序参数，因此以 `limit=100&offset=…` 分页读取，集中筛选、排序，再按 12 项分页。更大规模建议后端补服务端排序及 total。
- `pdf-lib` 仅在打开合并 / 拆分操作时动态加载，处理发生在浏览器中，生成文件仍通过现有上传接口校验。合并保留页面内容和页序，不承诺保留跨文档书签、附件、签名或可编辑表单；带数字签名的文件应保留原件。
- 批量操作逐项调用既有接口，显示成功 / 失败数量与原因，不把部分失败隐藏为成功。上传成功但分类 / 标签保存失败时，重试复用 file ID，不再次上传原文件。
- 后端时间为 naive UTC；显示时按 UTC 解析到本地时区，分享有效期提交 naive UTC，以兼容当前后端日期比较。
- 前端 viewer 隐藏或禁用写操作，管理员页面使用角色守卫；服务端仍是权限校验的最终边界。

## 验证

```bash
npm test
npm run build
# 首次安装测试用的 Chromium
npx playwright install chromium-headless-shell
npm run test:e2e
```

浏览器测试自动启动临时 Vite 服务，使用独立 Chromium 和页面级 API 契约夹具，覆盖登录返回、文件管理、上传失败重试、合并拆分、回收站、分享与撤销、只读限制、检索转义、管理员操作、401、改密、窄屏，以及缺失接口和补齐接口两种状态。**契约夹具测试不等同于真实后端或 OCR 推理验收**。

`tests/management.test.mjs` 验证真实 PDF 页序、拆分页段、100 页限制、文件名去重、分类 / 标签规则、时间口径及浏览器缓存隔离。原有第 03 线测试继续运行。

如需使用自己安装的 Chrome，可设置 `PLAYWRIGHT_CHANNEL=chrome`；测试默认使用与 Playwright 配套的 Chromium，避免系统浏览器版本差异。测试产物位于已忽略的 `test-results/`。

### 真实接口冒烟测试（可选）

安装好主系统 Python 依赖后，在前端目录依次启动三个终端：

```bash
# 终端一：使用独立临时数据库，关闭 OCR，不读取项目 .env
python scripts/start-smoke-api.py
# 终端二
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
# 终端三：无需接口拦截器，使用真实 FastAPI 服务
node scripts/live-smoke.mjs
```

该脚本创建测试账号与 PDF，验证注册、上传归档、合并拆分、分享提取码与下载、撤销、删除还原、统计、改密、令牌轮换和登出。**只对临时环境运行**；停止 `start-smoke-api.py` 后临时数据会清理。不会启动或执行 OCR 推理。
